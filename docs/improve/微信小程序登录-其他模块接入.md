# 微信小程序登录 — 其他模块如何接入

> **定位**：`/sys/wxMini/*` 是 **系统公共登录**，不隶属于提案模块。  
> **关联**：[微信授权登录-生命周期脉络.md](./微信授权登录-生命周期脉络.md)  
> **整理日期**：2026-09-01

先判断你要接的是 **同一个小程序**，还是 **另一个 AppID**。两条路改动差很多。

---

## 现在已经具备、一般不用再改的后端

| 能力 | 位置 | 说明 |
|------|------|------|
| 静默登录 | `POST /sys/wxMini/silentLogin` | 匿名；`jsCode` → OpenID；已绑定则发 APP Token |
| 绑定前校验工号 | `POST /sys/wxMini/checkWorkNo` | 匿名；仅查 `sys_user` 是否存在且有效，不调微信 |
| 首次绑定 | `POST /sys/wxMini/bind` | 匿名；工号 + `phoneCode`；空手机号回填 |
| 管理端解绑 | `POST /sys/wxMini/unbind` | 需登录；用户列表「更多 → 解绑微信」已接 |
| 配置 | `jeecg.wx-mini.app-id` / `app-secret` | 只放后端 yml |
| 绑定表 | `sys_third_account`，`third_type = wechat_mp` | OpenID ↔ `sys_user` |
| Shiro | `/sys/wxMini/silentLogin`、`/bind`、`/checkWorkNo` 已 `anon` | |

**不要**再为「考勤 / 报工 / 另一个菜单」复制一套 Controller。登录与业务模块解耦。

---

## 路径 A：还是公司这一个小程序（同一 AppID）

典型：在现有 `spex-app` 里加页面，或新做一个 uni-app，但公众平台仍是现在这个小程序。

**后端：零改动。**

前端要做的：

1. 请求基址仍指向本 Jeecg（须带 `/jeecg-boot`）。  
2. 登录页复用同一套调用（可直接抄 `spex-app`）：
   - 进页：`wx.login` → `silentLogin`
   - 未绑定：工号 + `getPhoneNumber` →（回调内先 `checkWorkNo`）→ `bind`
   - 工号+密码：`POST /sys/mLogin`（本来就是系统接口）
3. 登录成功后的 Token 与现在一样，请求头 `X-Access-Token`。  
4. **不要**把 AppSecret 写进小程序。

管理端解绑不用加菜单，系统管理 → 用户管理即可。

---

## 路径 B：新的 H5 / 管理端页面，不是小程序

**不能**复用 `getPhoneNumber` / `bind` 的微信授权（那是小程序按钮能力）。

- 浏览器：继续工号+密码（`/sys/login` 或 `/sys/mLogin`）。  
- 若将来要在 H5 用微信，那是开放平台网页授权，**另一套接口**，不是现在的 `/sys/wxMini`。

---

## 路径 C：另一个微信小程序（另一个 AppID）

OpenID **按小程序隔离**。现在配置和绑定表都按 **一个** AppID 设计，直接拿去接第二个小程序会串号或换 secret 失败。

需要改的逻辑（做到那一天再做，当前未实现）：

1. **配置**：`jeecg.wx-mini` 从单组 app-id/secret，改成按 AppID 列表（或 `app-id → secret` 映射）。  
2. **入参**：`silentLogin` / `bind` 增加明确的 `appId`（或独立 client 标识），后端用对应 secret 调 `jscode2session`。  
3. **绑定表**：`sys_third_account` 必须能区分小程序，例如：
   - `third_type` 仍为 `wechat_mp`，另存 `appId`，或  
   - `third_type` 做成 `wechat_mp_{appId}`  
   否则 A 小程序绑的 OpenID 会被 B 小程序误判为已绑定。  
4. **解绑**：管理端要知道解的是哪一个小程序；一个人可能绑多个 App。  
5. **前端**：新工程 `project.config.json` / `VITE_WX_APPID` 用新 AppID；微信公众平台把开发者加到 **那个** 小程序上。

在此之前，第二个小程序不要共用现在这一套。

---

## 接入时对照清单（路径 A）

- [ ] 员工已在 `sys_user`（`username` = 工号）  
- [ ] 空手机号允许首次绑定回填；已有号必须与微信授权号一致  
- [ ] 小程序请求打到 `/jeecg-boot/sys/wxMini/*`  
- [ ] 本地开发者工具勾选不校验合法域名  
- [ ] 正式环境配置 request 合法域名（HTTPS）  
- [ ] 不新增 Java Controller；业务接口仍放各业务模块  

---

## 一句话

| 场景 | 怎么做 |
|------|--------|
| 同一小程序、新业务页 | 只改前端，继续调 `/sys/wxMini` |
| 新 uni-app、同一 AppID | 抄登录页 + 配同一后端，后端不改 |
| 管理端 / H5 | 不要接 `bind`，用工号密码 |
| 新的小程序 AppID | 先扩展配置和绑定表，再接 |
