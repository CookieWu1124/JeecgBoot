### 请先读（最短对接路径）

1. **登录两种并存，不要做第三种。** 工号+密码（H5/小程序均可）与工号+微信授权（**仅小程序**）。不要做「工号+手填手机号」。登录成功后**不选部门**，直接进工作台。

4. **AppID 可以进前端，AppSecret 不行。** 前端只用 `spex-app/env/.env` 的 `VITE_WX_APPID`（当前 `wxce3a1b42d7fa0bd6`）。Secret 只在后端 `jeecg.wx-mini`。
5. **退出不解绑。** 调 `GET /sys/logout` 并清本地 Token 即可。解绑在管理端用户列表，见 [提案管理端-接口对接清单.md](./提案管理端-接口对接清单.md) S7。

## 1. 联调约定（先看这段）

| 项 | 说明 |
|----|------|
| Base URL | `http://{host}:8080/jeecg-boot` |
| 鉴权 | 请求头 `X-Access-Token: <JWT>`（与管理端同一套） |
| 登录 | **两种并存**（见 §3）：① 工号+密码 `POST /sys/mLogin`（H5/小程序均可）；② 工号+微信授权 `POST /sys/wxMini/*`（**仅小程序**，Chrome H5 测不了）。登录后**不选部门** |
| 密码 | **禁止明文**：AES-CBC + PKCS7，Key/IV 见下文 A1；示例代码见 `spex-app/src/utils/cipher.ts` |
| Content-Type | JSON 接口：`application/json` |
| 上传 | `multipart/form-data` → `/sys/common/upload` |
| 统一响应 | Jeecg `Result`：`{ success, code, message, result }`；业务成功常见 `code` 为 `200` 或 `0` |
| 业务报错 | `success=false`，`message` 为中文提示，前端直接 toast 即可 |
| Knife4j | `http://localhost:8080/jeecg-boot/doc.html` → 标签「提案业务」「微信小程序登录」 |

### 1.1 路径前缀约定

| 前缀 | 用途 | 本清单 |
|------|------|--------|
| `/proposal/**` | **共用**（小程序主链路） | ✅ 重点 |
| `/proposal/meta/**` | 元数据 | ✅ |
| `/sys/**` | 登录 / 上传 / 微信小程序登录 | ✅ 必要 |
| `/proposal/admin/**` | 管理端 | ❌ 不对接 |
| `/proposal/app/**` | 小程序首页聚合 | ✅ `GET /proposal/app/home` |

### 1.2 申请段状态流转（前端展示用）

```text
POST /proposal/create ──► PENDING_REVIEW（审核中）── review_progress: 0/N → N/N
              └─ 委员全部提交 ──► PENDING_APPROVAL（待批准）
                                    ├─ 批准 ──► APPROVED（已批准）← 申请段结束；阶段2待定，不是待指派
                                    └─ 不批准 ──► REJECTED_FINAL（不批准）
```

申请段**没有暂存、没有撤回**。`PENDING_ASSIGN` 不进 `GET /proposal/meta/statuses` 默认列表。无 `DRAFT` / `WITHDRAWN`。

发起页两步只是前端确认，点提交才调一次 `POST /proposal/create`，直接进入审核中。

| 状态码 | 中文 | 谁可操作 |
|--------|------|----------|
| `PENDING_REVIEW` | 审核中 | 委员：审 |
| `PENDING_APPROVAL` | 待批准 | 批准人：决策 |
| `APPROVED` | 已批准 | 申请段通过（阶段 2 待定） |
| `REJECTED_FINAL` | 不批准 | 终态 |

改善性质（多选，存 JSON 数组字符串）：码来自配置表 `proposal_improvement_type`，**不要写死**。发起页芯片调 `GET /proposal/meta/improvementTypes`（默认仅启用）。列表/详情优先用行内 `improvementTypesLabel`。种子码仍为：

| value | 文案（种子，可在管理端改名/停用/新增） |
|-------|------|
| `SAFETY` | 安全改善 |
| `QUALITY` | 品质改善 |
| `EFFICIENCY` | 效率改善 |
| `DELIVERY` | 交付改善 |
| `COST` | 成本改善 |

示例：`improvementTypes = "[\"SAFETY\",\"EFFICIENCY\"]"`

## 3. 鉴权与基础设施

### A1 登录

```http
POST /sys/mLogin
Content-Type: application/json
```

```json
{
  "username": "600081",
  "password": "<AES-CBC 加密后的 Base64 密文，不要传明文>"
}
```

| 字段 | 说明 |
|------|------|
| `username` | 工号（`workNo`） |
| `password` | **必须先 AES-CBC 加密再传**；明文会被后端鉴权失败（或按环境回退策略不稳定，联调请一律加密） |
| `loginOrgCode` | 可选；多部门时传所选 `orgCode` |

成功后取 `result.token`，后续请求带：

```http
X-Access-Token: <token>
```

#### ⚠️ 密码加密（必读）

与管理端 `jeecgboot-vue3`、后端 `org.jeecg.common.util.encryption.EncryptedString` **同一套参数**：

| 项 | 值 |
|----|-----|
| 算法 | AES |
| 模式 | CBC |
| 填充 | PKCS7 |
| Key（16 字节） | `1234567890adbcde` |
| IV（16 字节） | `1234567890hjlkew` |
| 输出 | CryptoJS 默认 **Base64** 字符串（即 `.toString()`） |

> 依赖：`crypto-js`。Key/IV 改了必须与后端同步，否则登录必失败。  
> 同源参考：`spex-app/src/utils/cipher.ts`、`spex-app/src/api/login.ts`  
> 同样需要加密的接口：`POST /sys/loginGetUserDeparts`（取部门列表）的 `password` 字段。

**加密工具示例（可直接拷贝）：**

```ts
// spex-app/src/utils/cipher.ts
import CryptoJS from 'crypto-js'

/** 与后端 EncryptedString.key 一致，长度 16 */
export const AES_KEY = '1234567890adbcde'
/** 与后端 EncryptedString.iv 一致，长度 16 */
export const AES_IV = '1234567890hjlkew'

/**
 * AES CBC + PKCS7 加密，输出 CryptoJS 默认 Base64 密文
 * 后端 AesEncryptUtil.resolvePassword 可解密
 */
export function encryptAESCBC(plainText: string): string {
  if (!plainText)
    return plainText
  const key = CryptoJS.enc.Utf8.parse(AES_KEY)
  const iv = CryptoJS.enc.Utf8.parse(AES_IV)
  return CryptoJS.AES.encrypt(plainText, key, {
    iv,
    mode: CryptoJS.mode.CBC,
    padding: CryptoJS.pad.Pkcs7,
  }).toString()
}
```

**调用示例：**

```ts
// spex-app/src/api/login.ts（节选）
import { encryptAESCBC } from '@/utils/cipher'

export function login(loginForm: { username: string, password: string, orgCode?: string }) {
  return http.post('/sys/mLogin', {
    username: loginForm.username,
    password: encryptAESCBC(loginForm.password), // ← 明文先进加密，再作为 body.password
    loginOrgCode: loginForm.orgCode,
  })
}
```

### A1a / A1b 微信授权登录（仅小程序）

系统公共接口，Knife4j 标签 **「微信小程序登录」**。H5 / Chrome **不要对接** `bind`（没有 `getPhoneNumber`）。参考实现：`spex-app/src/api/login.ts`、`spex-app/src/pages/login/index.vue`。

**推荐流程：**

```text
打开登录页
  → wx.login() 得到 jsCode
  → POST /sys/wxMini/silentLogin { jsCode }
      ├─ result.bound=true 且有 token → 直接进工作台（已绑定过）
      └─ bound=false → 停留登录页，用户填工号

用户点「微信授权登录」（button open-type="getPhoneNumber"）
  → 允许后拿到 e.detail.code（这是 phoneCode，不是手机号）
  → 再 wx.login() 拿一份新的 jsCode（一次性，用过即废）
  → POST /sys/wxMini/bind { jsCode, workNo, phoneCode }
      → 成功则 result.token，进工作台
```

用户点「退出登录」只清本地 Token；**不要**调解绑。主动退出后请 **不要立刻再调 silentLogin**（否则登录页会一闪又自动进来）。本仓库用本地标记 `wx-skip-silent-login`，下次手动登录成功后再清掉。解绑是管理端能力（见管理端清单 S7）。

测别人角色（委员/批准人）：用工号+密码即可。真机微信授权只能绑**当前微信对应的那个工号**。

#### A1a 静默登录（匿名，无需 Token）

```http
POST /sys/wxMini/silentLogin
Content-Type: application/json
```

```json
{ "jsCode": "<wx.login 返回的 code>" }
```

| `result` | 说明 |
|----------|------|
| `{ "bound": false }` | 该微信未绑工号，停在登录页 |
| `{ "bound": true, "token": "...", "userInfo": { ... } }` | 已绑定，签发 **APP JWT**（与 mLogin 相同用法） |

#### A1b 首次绑定（匿名，无需 Token）

```http
POST /sys/wxMini/bind
Content-Type: application/json
```

```json
{
  "jsCode": "<本次重新 wx.login 的 code>",
  "workNo": "600099",
  "phoneCode": "<getPhoneNumber 的 e.detail.code，不要传 11 位手机号>"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `jsCode` | 是 | 小程序 `wx.login` / `uni.login` 的 code，一次性 |
| `workNo` | 是 | 工号 = `sys_user.username` |
| `phoneCode` | 是 | 微信手机号授权码；后端向微信换真实手机号，**前端不要自己填手机号** |

成功 `result` 与静默登录已绑定相同：`bound=true`、`token`、`userInfo`。请求头同样带 `X-Access-Token`。绑定写入 `sys_third_account`（`third_type = wechat_mp`）。已绑**当前**微信时会直接发 Token，**不再比手机号**。

登录成功后**不要**再调 `POST /sys/loginGetUserDeparts` 让用户选部门，直接进工作台。

**手机号规则（后端）：**

| `sys_user.phone` | 行为 |
|------------------|------|
| `null` / 空 | 放行，并把微信手机号回填到该用户 |
| 已有号码且与微信授权号一致 | 放行 |
| 已有号码但不一致 | `工号与手机号不一致，请联系管理员修正用户信息` |
| 微信手机号已被 **其他用户** 占用（含已解绑未清号） | `该手机号已被其他用户占用（姓名 / 工号），请联系管理员处理` |

号码占用**不会**自动从别人档案挪走。管理员在用户管理改号；改号 ≠ 解绑（OpenID 仍在绑定表）。

其它业务提示（前端直接 toast `message`，括号内为占用方标签）：

| `message`（原文或前缀） | 含义 |
|-------------------------|------|
| `该微信已绑定其他工号（姓名 / 工号），请联系管理员解绑` | 这个微信已绑别的工号；管理端给**对方**解绑 |
| `该工号已绑定其他微信，请联系管理员解绑` | 这个工号已绑别的微信 |
| `工号无效，请重新输入` | `sys_user.username` 无此账号 |
| `请输入工号` | 没传 `workNo` |
| `缺少微信登录凭证` / `缺少手机号授权` | 没传 `jsCode` / `phoneCode` |
| 含 `code been used` / `invalid code` | `jsCode` 过期或复用，重新 `wx.login` |

#### A1c 退出登录

```http
GET /sys/logout
X-Access-Token: <token>
```

只作废当前 Token。**不要**调 `/sys/wxMini/unbind`。前端同时清本地 Token，并跳过下一次静默登录（见上文）。

**不要做的事：**

- 不要把 AppSecret 写进小程序
- 不要把 `phoneCode` 当手机号展示或落库
- 不要复用过期的 `jsCode`（报 `code been used` 时重新 `wx.login`）
- Chrome H5 点微信授权应提示去小程序，不要调 A1b

本地联调：开发者工具打开 `spex-app/dist/dev/mp-weixin`，勾选「不校验合法域名」；步骤见 [微信开发者工具-小程序联调教程.md](../微信开发者工具-小程序联调教程.md)。

### A2 现场图片上传

```http
POST /sys/common/upload
Content-Type: multipart/form-data
X-Access-Token: <token>
```

```http
GET /proposal/meta/improvementDepts
```

**`result` 数组元素：**

| 字段 | 类型 | 说明 |

### B2 提案状态下拉（枚举，非字典）

```http
GET /proposal/meta/statuses
```

文案唯一来源：后端 `ProposalStatusEnum`。列表/详情行上同时带 `statusLabel`，展示优先用行内字段；本接口给筛选下拉。

**`result` 数组元素：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | string | 落库状态码，如 `PENDING_REVIEW` |
| `label` | string | 中文，如 `审核中` |
| `terminal` | boolean | 申请段闭环：已批准 / 不批准 为 true |

默认只返回申请段四档。需要全量枚举时加 `?applicationOnly=false`。

### B3 改善性质芯片/下拉（配置表，非字典）

```http
GET /proposal/meta/improvementTypes?enabledOnly=true
```

文案来源：`proposal_improvement_type`。默认只返回启用项（发起芯片、管理端筛选）。`enabledOnly=false` 含停用行，用于旧单回显。列表/详情行上同时带 `improvementTypesLabel`。

**`result` 数组元素：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | string | 落库码，如 `SAFETY` |
| `label` | string | 中文，如 `安全改善` |
| `typeStatus` | string | `active` / `disabled` |
| `sortNo` | number | 排序 |
| `description` | string | 说明，可空 |

## 5. 提案人：发起 / 列表 / 详情

### C1 发起提案（一次提交）

```http
POST /proposal/create
```

**Body：**

```json
{
  "title": "车间灯光太阳能改善测试001",
  "improvementTypes": "[\"SAFETY\",\"EFFICIENCY\"]",
  "deptId": "spexdeptgroupelc0000000000001",
  "teamType": "PERSONAL",
  "currentSituation": "目前状况……",
  "improvementSuggestion": "改善意见……",
  "attachments": [
    {
      "fileName": "现场1.jpg",
      "fileUrl": "/sys/common/static/xxx.jpg",
      "fileSize": 123456
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | 是 | 提案名称 |
| `improvementTypes` | 是 | JSON 数组**字符串**（码须为当前启用的改善性质；来自 B3） |
| `deptId` | 是 | 来自 B1 |
| `currentSituation` | 是 | 目前状况 |
| `improvementSuggestion` | 是 | 改善意见 |
| `teamType` | 否 | 如 `PERSONAL` |
| `attachments` | 否 | 0～4 |

**`result`：** 提案主键 `id`（string）。成功后状态即为 `PENDING_REVIEW`（审核中），生成 `proposalNo`，`reviewProgress` 为 `0/N`，并写入委员审核快照。

失败常见原因：未配部门负责人、委员会为空、必填正文缺失。

### C3 单独提交（已并入 C1）

```http
PUT /proposal/{id}/submit
```

不要再先 create 再 submit。若在 C1 之后再调本接口，且状态已是审核中，会幂等成功；其它状态会失败。

### C5 我的提案列表


## 6. 委员审核

> 身份：用户在 `proposal_committee_member` 在任名册中。  
> 每人一票，**提交后不可改**；全部提交后自动进入 `PENDING_APPROVAL`。

### D1 委员待审列表

```http
GET /proposal/review/committee/pending?pageNo=1&pageSize=20
```

返回：状态为 `PENDING_REVIEW` 且**当前用户尚未提交意见**的提案分页。

每条带委员汇总（未审完也可能是部分票）和人员部门嵌套。**字段名与 JSON 样例见 [E1](#e1-批准人待办)**，D1 / E1 / C5 同一套。

非委员调用：业务提示无权限 / 不在名册。

### D2 委员提交意见

```http
POST /proposal/review/committee/{proposalId}
```

**采用：**

```json
{
  "conclusion": "ADOPT",
  "planRequired": 1,
  "awardSuggestion": 150,
  "comment": "可选说明"
}
```

**不采用：**

```json
{
  "conclusion": "REJECT",
  "comment": "不采用原因（必填）"
}
```

| 字段 | 采用 | 不采用 |
|------|------|--------|
| `conclusion` | `ADOPT` | `REJECT` |
| `planRequired` | **必填** `0`/`1` | 忽略 |
| `awardSuggestion` | 可选 number | 忽略 |
| `comment` | 可选 | **必填** |

成功后该提案 `reviewProgress` 递增；最后一人提交触发 → `PENDING_APPROVAL`。

## 7. 批准人申请决策

> 身份：`proposal_approver` 在任。通常**全局一人**。  
> E1 非批准人返回空分页（与 D1 委员待审一致）；E2 写操作仍会失败。待办页可并行调 D1+E1，无需先判断角色。

### E1 批准人待办

```http
GET /proposal/approval/pending?pageNo=1&pageSize=20
```

在任批准人返回所有 `PENDING_APPROVAL` 提案分页；非批准人返回空分页（`records=[]`，`total=0`）。待办卡片用的委员汇总、人员部门嵌套一并带回，无需再调详情。

**画面文案 ↔ JSON 字段名（抓报文对照）：**

| 画面 | JSON 路径 | 说明 |
|------|-----------|------|
| 采用 4 | `adoptCount` | 委员 `conclusion=ADOPT` 人数 |
| 不采用 1 | `rejectCount` | 委员 `conclusion=REJECT` 人数 |
| 委员会 5/5 | `reviewProgress` | 主表已有，字符串 `"5/5"` |
| 建议形成计划书 | `planRequiredSuggest` | `1` 形成 / `0` 不形成；尚无采用票则为 `null` |
| 奖励 ¥200 | `awardSuggestAmount` | 采用票奖励建议众数；批准前主表 `awardAmount` 仍为 `null` |
| 品质部 | `dept.departName` | 改善部门嵌套 |
| 刘洋 | `proposer.realname` | 提案人嵌套 |

口径：只统计已提交结论；`planRequiredSuggest` / `awardSuggestAmount` 只看 **ADOPT** 票。不要和批准人核定后的 `planRequired` / `awardAmount` 混用。

### E2 申请批准决策

```http
POST /proposal/approval/application/{proposalId}
```

**批准：**

```json
{
  "decision": "APPROVE",
  "planRequired": 1,
  "awardAmount": 150,
  "comment": "可选"
}
```

→ 状态 `APPROVED`（已批准，申请段结束）；主表写入 `plan_required`、`award_amount`。**不会**变成 `PENDING_ASSIGN`。

**不批准：**

```json
{
  "decision": "REJECT",
  "comment": "不批准原因（必填）"
}
```

→ 状态 `REJECTED_FINAL`。

| 字段 | 批准 | 不批准 |
|------|------|--------|
| `decision` | `APPROVE` | `REJECT` |
| `planRequired` | **必填** `0`/`1` | 忽略 |
| `awardAmount` | 建议填写 | 忽略 |
| `comment` | 可选 | **必填** |

同一提案申请阶段决策**只能一次**。

### F1 首页聚合

```http
GET /proposal/app/home
```

登录即可调，**不按 Jeecg 角色抛错**。待办/动态按**配置名册上的位置**并集：提案人、委员快照、在任批准人、改善部门负责人。同一人多顶帽子会合并。申请人本身没有可操作待办时 `todoItems=[]` 是正常的。

| 字段 | 口径 |
|------|------|
| `todoCount` / `todoItems` | 委员未审（主表仍审核中）+ 在任批准人待核定 + 部门负责人待指派；列表最多 **5** 条 |
| `todoItems[].kind` | `review` 跳审核页；`approve` 跳批准页；`assign` 跳详情（任务分配阶段 2 尚未交付，当前几乎为空） |
| `doingCount` | 自己作为提案人、非终态（申请段即审核中/待批准） |
| `doneCount` | 自己作为提案人：已批准 / 不批准 / 已结案 |
| `feeds` | 与当前人相关的 `status_log`，SQL **只取最近 5 条**（提案人自己的单 ∪ 委员快照内 ∪ 部门负责人名下 ∪ 批准人待核定/已决策） |

## 10. 前端注意点（踩坑清单）

1. **登录密码必须 AES 加密**：`/sys/mLogin`（及 `loginGetUserDeparts`）的 `password` 传密文，算法与 Key/IV 见 §3 A1；明文联调易失败。
2. **微信授权仅小程序**：`phoneCode` 不是手机号；H5 不要调 `/sys/wxMini/bind`。退出登录不解绑；主动退出后不要马上 silentLogin。AppSecret 不要进小程序。
3. **`improvementTypes` 是字符串**：`JSON.stringify([...])`，不要直接传数组（除非你们改了后端；当前后端按 string 收）。
4. **委员意见不可二次提交**：按钮提交成功后应禁用/返回待办。
5. **批准人 pending 对全员安全**：非批准人调 E1 返回空分页（`records=[]`），**不会**业务报错；待办页可并行调 D1+E1。写操作 E2 非批准人仍会失败。
6. **`reviewProgress` 展示**：字符串如 `"3/5"`，列表/详情直接显示。
7. **`planRequired`**：`0` 不形成计划书，`1` 形成；委员是「建议」，批准人是「核定」并落主表。
8. **Token 失效**：按 Jeecg 约定跳转登录；不要静默吞。
9. **登录**：联调必须用工号真实登录，假 Token 打不到后端。
10. **首页按位置展示**：待办读配置名册（委员快照 / 批准人 / 部门负责人），不是 `sys_role`。贺志龙是纯提案人时「我的待办」为空正常；委员/批准人登录会看到对应待办。动态按上述位置并集，**只返回 5 条**。
