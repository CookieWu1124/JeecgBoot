## 1. 联调约定（先看这段）

| 项 | 说明 |
|----|------|
| Base URL | `http://{host}:8080/jeecg-boot` |
| 鉴权 | 请求头 `X-Access-Token: <JWT>`（与管理端同一套） |
| 登录 | `POST /sys/mLogin`，`username` = **工号**（`workNo`） |
| 密码 | **禁止明文**：AES-CBC + PKCS7，Key/IV 见下文 A1；示例代码见 `spex-app/src/utils/cipher.ts` |
| Content-Type | JSON 接口：`application/json` |
| 上传 | `multipart/form-data` → `/sys/common/upload` |
| 统一响应 | Jeecg `Result`：`{ success, code, message, result }`；业务成功常见 `code` 为 `200` 或 `0` |
| 业务报错 | `success=false`，`message` 为中文提示，前端直接 toast 即可 |
| Knife4j | `http://localhost:8080/jeecg-boot/doc.html` → 标签「提案业务」 |

### 1.1 路径前缀约定

| 前缀 | 用途 | 本清单 |
|------|------|--------|
| `/proposal/**` | **共用**（小程序主链路） | ✅ 重点 |
| `/proposal/meta/**` | 元数据 | ✅ |
| `/sys/**` | 登录 / 上传 | ✅ 必要 |
| `/proposal/admin/**` | 管理端 | ❌ 不对接 |
| `/proposal/app/**` | 小程序首页聚合（可选） | ⚪ 可选 |

### 1.2 申请段状态流转（前端展示用）

```text
DRAFT（草稿）
  └─ submit ──► PENDING_REVIEW（待审核）── review_progress: 0/N → N/N
                    ├─ withdraw（仅提案人）──► WITHDRAWN（已撤回）
                    └─ 委员全部提交 ──► PENDING_APPROVAL（待批准 / 待核定）
                                          ├─ 批准 ──► PENDING_ASSIGN（待指派）← 下一段入口
                                          └─ 不批准 ──► REJECTED_FINAL（不批准）
```

| 状态码 | 中文（建议文案） | 谁可操作 |
|--------|------------------|----------|
| `DRAFT` | 草稿 | 提案人：编辑 / 提交 |
| `PENDING_REVIEW` | 待审核 | 委员：审；提案人：撤回 |
| `PENDING_APPROVAL` | 待批准 / 待核定 | 批准人：决策 |
| `REJECTED_FINAL` | 不批准 | 终态 |
| `WITHDRAWN` | 已撤回 | 终态 |
| `PENDING_ASSIGN` | 待指派 | **下一段**，本清单不做 |

改善性质（多选，存 JSON 数组字符串）：码来自配置表 `proposal_improvement_type`，**不要写死**。发起页芯片调 `GET /proposal/meta/improvementTypes`（默认仅启用）。列表/详情优先用行内 `improvementTypesLabel`。种子码仍为：

| value | 文案（种子，可在管理端改名/停用/新增） |
|-------|------|
| `SAFETY` | 安全改善 |
| `QUALITY` | 品质改善 |
| `EFFICIENCY` | 效率改善 |
| `DELIVERY` | 交付改善 |
| `COST` | 成本改善 |

示例：`improvementTypes = "[\"SAFETY\",\"EFFICIENCY\"]"`

## 3. 鉴权与基础设施

### A1 登录

```http
POST /sys/mLogin
Content-Type: application/json
```

```json
{
  "username": "600081",
  "password": "<AES-CBC 加密后的 Base64 密文，不要传明文>"
}
```

| 字段 | 说明 |
|------|------|
| `username` | 工号（`workNo`） |
| `password` | **必须先 AES-CBC 加密再传**；明文会被后端鉴权失败（或按环境回退策略不稳定，联调请一律加密） |
| `loginOrgCode` | 可选；多部门时传所选 `orgCode` |

成功后取 `result.token`，后续请求带：

```http
X-Access-Token: <token>
```

#### ⚠️ 密码加密（必读）

与管理端 `jeecgboot-vue3`、后端 `org.jeecg.common.util.encryption.EncryptedString` **同一套参数**：

| 项 | 值 |
|----|-----|
| 算法 | AES |
| 模式 | CBC |
| 填充 | PKCS7 |
| Key（16 字节） | `1234567890adbcde` |
| IV（16 字节） | `1234567890hjlkew` |
| 输出 | CryptoJS 默认 **Base64** 字符串（即 `.toString()`） |

> 依赖：`crypto-js`。Key/IV 改了必须与后端同步，否则登录必失败。  
> 同源参考：`spex-app/src/utils/cipher.ts`、`spex-app/src/api/login.ts`  
> 同样需要加密的接口：`POST /sys/loginGetUserDeparts`（取部门列表）的 `password` 字段。

**加密工具示例（可直接拷贝）：**

```ts
// spex-app/src/utils/cipher.ts
import CryptoJS from 'crypto-js'

/** 与后端 EncryptedString.key 一致，长度 16 */
export const AES_KEY = '1234567890adbcde'
/** 与后端 EncryptedString.iv 一致，长度 16 */
export const AES_IV = '1234567890hjlkew'

/**
 * AES CBC + PKCS7 加密，输出 CryptoJS 默认 Base64 密文
 * 后端 AesEncryptUtil.resolvePassword 可解密
 */
export function encryptAESCBC(plainText: string): string {
  if (!plainText)
    return plainText
  const key = CryptoJS.enc.Utf8.parse(AES_KEY)
  const iv = CryptoJS.enc.Utf8.parse(AES_IV)
  return CryptoJS.AES.encrypt(plainText, key, {
    iv,
    mode: CryptoJS.mode.CBC,
    padding: CryptoJS.pad.Pkcs7,
  }).toString()
}
```

**调用示例：**

```ts
// spex-app/src/api/login.ts（节选）
import { encryptAESCBC } from '@/utils/cipher'

export function login(loginForm: { username: string, password: string, orgCode?: string }) {
  return http.post('/sys/mLogin', {
    username: loginForm.username,
    password: encryptAESCBC(loginForm.password), // ← 明文先进加密，再作为 body.password
    loginOrgCode: loginForm.orgCode,
  })
}
```

### A2 现场图片上传

```http
POST /sys/common/upload
Content-Type: multipart/form-data
```

## 4. 元数据

### B1 改善部门下拉

```http
GET /proposal/meta/improvementDepts
```

**`result` 数组元素：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `deptId` | string | 改善部门 ID（提交时用） |
| `deptName` | string | 部门名称 |

| `leaderName` | string | 负责人姓名（可空） |

### B2 提案状态下拉（枚举，非字典）

```http
GET /proposal/meta/statuses
```

文案唯一来源：后端 `ProposalStatusEnum`。列表/详情行上同时带 `statusLabel`，展示优先用行内字段；本接口给筛选下拉。

**`result` 数组元素：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | string | 落库状态码，如 `PENDING_REVIEW` |
| `label` | string | 中文，如 `待审核` |
| `terminal` | boolean | 是否终态（不批准 / 已撤回 / 已完成） |

### B3 改善性质芯片/下拉（配置表，非字典）

```http
GET /proposal/meta/improvementTypes?enabledOnly=true
```

文案来源：`proposal_improvement_type`。默认只返回启用项（发起芯片、管理端筛选）。`enabledOnly=false` 含停用行，用于旧单回显。列表/详情行上同时带 `improvementTypesLabel`。

**`result` 数组元素：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | string | 落库码，如 `SAFETY` |
| `label` | string | 中文，如 `安全改善` |
| `typeStatus` | string | `active` / `disabled` |
| `sortNo` | number | 排序 |
| `description` | string | 说明，可空 |

### C2 更新草稿

```http
PUT /proposal/{id}/draft
```

Body 同 C1；仅 `DRAFT` 可更新。

### C3 提交申请

```http
PUT /proposal/{id}/submit
```

无 Body。成功后：

- 状态 → `PENDING_REVIEW`
- 生成 `proposalNo`（如 `202608290001`）
- `reviewProgress` 初始为 `0/N`（N = 当前在任委员数）
- 后端为每位委员写入审核快照行

失败常见原因：未配部门负责人、委员会为空、必填正文缺失、非草稿状态。

### C4 撤回

```http
POST /proposal/{id}/withdraw
```

仅 **提案人** + 状态 `PENDING_REVIEW`。成功 → `WITHDRAWN`，审核快照清理。

| `title` | — | 模糊搜标题 |
| `pageNo` / `pageSize` | 1 / 10 | 分页 |

## 6. 委员审核

> 身份：用户在 `proposal_committee_member` 在任名册中。  
> 每人一票，**提交后不可改**；全部提交后自动进入 `PENDING_APPROVAL`。

### D1 委员待审列表

```http
GET /proposal/review/committee/pending?pageNo=1&pageSize=20
```

返回：状态为 `PENDING_REVIEW` 且**当前用户尚未提交意见**的提案分页（结构同列表）。

非委员调用：业务提示无权限 / 不在名册。

### D2 委员提交意见

```http
POST /proposal/review/committee/{proposalId}
```

**采用：**

```json
{
  "conclusion": "ADOPT",
  "planRequired": 1,
  "awardSuggestion": 150,
  "comment": "可选说明"
}
```

**不采用：**

```json
{
  "conclusion": "REJECT",
  "comment": "不采用原因（必填）"
}
```

| 字段 | 采用 | 不采用 |
|------|------|--------|
| `conclusion` | `ADOPT` | `REJECT` |
| `planRequired` | **必填** `0`/`1` | 忽略 |
| `awardSuggestion` | 可选 number | 忽略 |
| `comment` | 可选 | **必填** |

成功后该提案 `reviewProgress` 递增；最后一人提交触发 → `PENDING_APPROVAL`。

## 7. 批准人申请决策

> 身份：`proposal_approver` 在任。通常**全局一人**。  
> 非批准人调 E1/E2 会失败；待办页应对 E1 **单独 catch**，避免整页挂掉。

### E1 批准人待办

```http
GET /proposal/approval/pending?pageNo=1&pageSize=20
```

返回所有 `PENDING_APPROVAL` 提案分页。

### E2 申请批准决策

```http
POST /proposal/approval/application/{proposalId}
```

**批准：**

```json
{
  "decision": "APPROVE",
  "planRequired": 1,
  "awardAmount": 150,
  "comment": "可选"
}
```

→ 状态 `PENDING_ASSIGN`；主表写入 `plan_required`、`award_amount`。

**不批准：**

```json
{
  "decision": "REJECT",
  "comment": "不批准原因（必填）"
}
```

→ 状态 `REJECTED_FINAL`。

| 字段 | 批准 | 不批准 |
|------|------|--------|
| `decision` | `APPROVE` | `REJECT` |
| `planRequired` | **必填** `0`/`1` | 忽略 |
| `awardAmount` | 建议填写 | 忽略 |
| `comment` | 可选 | **必填** |

同一提案申请阶段决策**只能一次**。

## 10. 前端注意点（踩坑清单）

1. **登录密码必须 AES 加密**：`/sys/mLogin`（及 `loginGetUserDeparts`）的 `password` 传密文，算法与 Key/IV 见 §3 A1；明文联调易失败。
2. **`improvementTypes` 是字符串**：`JSON.stringify([...])`，不要直接传数组（除非你们改了后端；当前后端按 string 收）。
3. **委员意见不可二次提交**：按钮提交成功后应禁用/返回待办。
4. **批准人 pending 非全员接口**：普通用户调会报错，待办里 catch 后展示空列表即可。
5. **`reviewProgress` 展示**：字符串如 `"3/5"`，列表/详情直接显示。
6. **`planRequired`**：`0` 不形成计划书，`1` 形成；委员是「建议」，批准人是「核定」并落主表。
7. **Token 失效**：按 Jeecg 约定跳转登录；不要静默吞。
8. **体验登录**：`spex-app` 假 Token **打不到后端**，联调必须用工号真实登录。
