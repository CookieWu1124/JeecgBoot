## 1. 联调约定（先看这段）

| 项 | 说明 |
|----|------|
| Base URL | `http://{host}:8080/jeecg-boot`；Vue3 开发环境走代理，`defHttp` 路径写相对路径即可 |
| 鉴权 | 请求头 `X-Access-Token: <JWT>`（Jeecg 管理端登录后自动带） |
| 登录 | `POST /sys/login`，`username` = **工号**（`workNo`）；密码走平台既有 AES，**不要自己再包一层** |
| Content-Type | JSON 接口：`application/json` |
| 统一响应 | Jeecg `Result`：`{ success, code, message, result }`；业务成功常见 `code` 为 `200` 或 `0` |
| 业务报错 | `success=false`，`message` 为中文提示，前端直接 `createMessage` 即可 |
| Knife4j | `http://localhost:8080/jeecg-boot/doc.html` → 标签「管理端-提案管理」「管理端-提案配置」「提案元数据」；**选人/选部门**见标签「系统-用户」「系统-部门」（见 §5.0） |
| 菜单 SQL | `docs/improve/sql/proposal_menu.sql`；执行后需在「角色管理」给 `admin` / `proposal_admin` 授权 |

### 1.1 路径前缀约定

| 前缀 | 用途 | 本清单 |
|------|------|--------|
| `/proposal/admin/manage/**` | 提案管理（后台列表/详情） | ✅ 重点 |
| `/proposal/admin/config/**` | 提案配置（五 Tab CRUD） | ✅ 重点 |
| `/proposal/meta/**` | 公共元数据（`ProposalMetaController`） | ✅ 筛选下拉全量，见 §4 |
| `/sys/**` | 登录、用户/部门回显、选人选部门 | ✅ 必要（名称不在业务接口里） |
| `/proposal/**`（`ProposalController`） | 共用生命周期：发起/撤回/委员审/批准 | ⚪ 已盘点；**管理端不对接**，见 §2.1 |
| `/proposal/app/**` | 小程序首页聚合 | ❌ 不对接 |
| `/proposal/admin/stats/**` | 管理端统计 | ❌ 尚未交付 |

### 1.2 页面范围（当前产品）

| 菜单 | 路由 | 组件 | 当前能力 |
|------|------|------|----------|
| 提案改善（目录） | `/proposal` | `layouts/RouteView` | — |
| 提案管理 | `/proposal/manage` | `mes/proposal/manage/index` | **仅查询 + 详情**，无新增/编辑/删除/勾选 |
| 提案配置 | `/proposal/config` | `mes/proposal/config/index` | 五 Tab 全量 CRUD |

> 后端虽保留 `POST /add`、`PUT /edit`、`DELETE /delete`，**当前管理端页面不要接**。提案的发起/审核/批准走小程序。

### 1.3 配置五 Tab

| Tab | 配置表 | 业务作用 |
|-----|--------|----------|
| 部门负责人 | `proposal_dept_leader` | 提交申请前校验；一部门一人 |
| 委员会 | `proposal_committee_member` | 审核名册；`scoreEnabled` 控制是否参与后期评分 |
| 批准人 | `proposal_approver` | 申请/计划书/报告书终审；列表接口只返回 `active` |
| 改善性质 | `proposal_improvement_type` | 发起页芯片 + 列表筛选；**不要写死码** |
| 评分维度 | `proposal_score_dimension` | 后期六维评分权重；本阶段只做配置维护 |

### 1.4 通用字段（所有 `proposal_*` 表）

保存时后端会补审计字段，前端**不必传** `createBy` / `updateBy`。列表展示可用 `updateBy`、`updateTime`。

| 字段 | 说明 |
|------|------|
| `id` | 主键；新增不传，编辑必传 |
| `createBy` / `createTime` | 创建人名称 / 时间 |
| `updateBy` / `updateTime` | 更新人名称 / 时间 |
| `remark` | 备注，可选 |
| `active` | 逻辑删除：`Y` 有效 / `N` 已删；列表默认只出有效行 |

### 2.1 公共 Controller 全量对照

包路径：`org.jeecg.modules.proposal.controller`（与 `admin/`、`app/` 平级）。  
**结论**：10 个生命周期接口管理端都不要调；3 个元数据接口管理端要用（B1 可选，B2/B3 必用）。

## 3. 提案管理

### M1 分页列表

```http
GET /proposal/admin/manage/list
```

走 Jeecg `QueryGenerator`：查询参数名与实体字段一致。分页：`pageNo`（默认 1）、`pageSize`（默认 10）。默认 `create_time` 倒序。

| 参数 | 对应筛选项 | 说明 |
|------|------------|------|
| `proposalNo` | 提案编号 | 精确；需要模糊可传 `*202608*` |
| `title` | 提案名称 | 同上 |
| `status` | 当前环节 | 状态码，来自 B2，如 `PENDING_REVIEW` |
| `deptId` | 改善部门 | `sys_depart.id`；`JSelectDept` 若返回数组/逗号串，**只取第一个** |
| `improvementTypes` | 改善性质 | 落库是 JSON 字符串。单选筛选请传 `*SAFETY*`（前后星号 = LIKE） |
| `proposerName` | 提案人 | **不是实体字段**；后端按 `sys_user.realname` 模糊搜 `proposer_id` |
| `createTime_begin` / `createTime_end` | 提交日期 | 日期范围，格式 `YYYY-MM-DD`；Vue3 可用 `fieldMapToTime` |

## 4. 元数据（筛选下拉，来自公共 `ProposalMetaController`）

三个接口都在 `/proposal/meta/**`，登录即可调，和小程序同一套。B4 仅配置弹窗选人预览用。

### B1 改善部门下拉（可选）

```http
GET /proposal/meta/improvementDepts
```

来自 `proposal_dept_leader`（`active=Y`），**已带部门名和负责人名**，不必再调 S2。只返回「配过改善部门」的行，比 `JSelectDept` 全组织树更贴筛选语义。

**`result` 数组元素：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `deptId` | string | 改善部门 ID（筛 `deptId` 用这个） |
| `deptName` | string | 部门名称 |
| `leaderUserId` | string | 负责人用户 ID，可空 |
| `leaderName` | string | 负责人姓名，未配置时为 `null` |
| `leaderConfigured` | boolean | 是否已配负责人 |

当前仓库列表筛选用的是 `JSelectDept`（全部门树）。若改成只筛「已配置改善部门」，直接接本接口即可。配置页「新增部门负责人」仍用 `JSelectDept`，因为要选尚未配置的部门。

### B2 提案状态

```http
GET /proposal/meta/statuses
```

来自后端枚举，**不是数据字典**。`result` 数组：`{ code, label, terminal }`。

申请段常见：`DRAFT` 草稿、`PENDING_REVIEW` 待审核、`PENDING_APPROVAL` 待批准、`REJECTED_FINAL` 不批准、`WITHDRAWN` 已撤回、`PENDING_ASSIGN` 待指派。后续状态也会返回，筛选下拉可全量展示。

### B3 改善性质

```http
GET /proposal/meta/improvementTypes?enabledOnly=true
```

来自配置表。默认只返回启用项（列表筛选、发起芯片）。`enabledOnly=false` 含停用，用于旧单回显。

`result` 数组：`{ code, label, typeStatus, sortNo, description }`。

种子码（可在配置里改名/停用/新增，**前端不要写死文案**）：

| code | 种子名称 |
|------|----------|
| `SAFETY` | 安全改善 |
| `QUALITY` | 品质改善 |
| `EFFICIENCY` | 效率改善 |
| `DELIVERY` | 交付改善 |
| `COST` | 成本改善 |

### B4 用户摘要（配置弹窗选中后预览）

```http
GET /proposal/meta/userBriefs?userIds=id1,id2
```

一次返回姓名、工号、职位、**所属部门名**。`userIds` 逗号分隔。`result` 为数组，元素：

| 字段 | 说明 |
|------|------|
| `id` | 用户主键 |
| `realname` | 姓名 |
| `workNo` | 工号；空则回退 `username` |
| `username` | 登录账号 |
| `positionType` | 职位 |
| `orgCode` | 所属组织编码 |
| `deptName` | 所属部门名称（后端按 `orgCode` 批量换出） |

**列表/详情不要调这个接口**，那些已经嵌了 `user` / `proposer` / `reviewer`。只给「添加委员」等弹窗，选中员工后预览用。

## 5. 系统接口（选人 / 选部门）

**列表、详情的姓名/部门已嵌在业务接口里**，不要再用 S1/S2/S3 循环回显。  
本节只覆盖选人/选部门弹窗（从全量组织里挑 id）。推荐 `JSelectUser` / `JSelectDept`。

### 5.0 为什么 Knife4j 里原先搜不到

平台 `Swagger3Config` 有全局过滤器：

```java
GlobalOpenApiMethodFilter → 方法必须带 @Operation 才会进文档
```

`SysUserController`、`SysDepartController` 原先**整类没有** `@Tag` / `@Operation`，所以 `doc.html` 里既不在「管理端-提案*」分组，也搜不到 `/sys/user/list`。  
**不是接口不存在**，登录后即可调。现已给本清单用到的 6 个方法补了注解，重启后端后可在：

| Knife4j 标签 | 接口 |
|--------------|------|
| **系统-用户** | S1 `queryByIds`、S4 `queryUserComponentData`、S5 `/list` |
| **系统-部门** | S2 `queryByIds`、S3 `getDepartName`、S6 `queryTreeList` |

其余系统 CRUD（用户增删改、部门增删改等）仍不进文档，提案管理端也不需要。

> 不要用 `GET /sys/user/queryById`：它带权限码 `system:user:queryById`，`proposal_admin` 未必有；回显一律用 S1。  
> 不要用 `GET /sys/user/listAll`：需要 `system:user:listAll`。选人用 S5。

### 5.1 三张弹窗 ↔ 接口

| 弹窗 | 交互 | 接口 | 组件（本仓库实现） |
|------|------|------|-------------------|
| 新增部门负责人 | 「改善部门」选择 | **S6** 部门树 | `JSelectDept`（`multiple=false`） |
| 新增部门负责人 | 「部门负责人」选择 | **S4** 按 `deptId` 过滤人员 | `JSelectUser` + `customListApi` |
| 添加委员会成员 | 「选择员工」 | **S5** 全量用户分页 | `JSelectUser`（`rowKey=id`） |
| 添加委员会成员 | 选中后展示姓名/工号/部门/职位 | **B4** | `getUserProfile` → `/proposal/meta/userBriefs` |
| 选择批准人 | 账号/姓名查询 + 分页表 | **S5** | `JSelectUser`（`rowKey=id`） |
| 各列表/详情回显姓名部门 | **已嵌套，不要二次查询** | C1/C4/C7/M1/M2 | `dept` / `user` / `proposer` / `reviewer` 等 |

### 5.2 用户对象常用字段（S1 / S4 / S5 的 `result` 元素）

实体 `SysUser`。`password` / `salt` 为 `WRITE_ONLY`，**JSON 里不会出现**。带 `@Dict` 的字段，字典切面会额外返回 `xxx_dictText`。

| 字段 | 类型 | 说明 | 提案配置怎么用 |
|------|------|------|----------------|
| `id` | string | 主键；**保存配置时传这个** | `leaderUserId` / `userId` |
| `username` | string | 登录账号；本环境 = **工号** | 选人表「用户账号」列 |
| `realname` | string | 姓名 | 列表/预览「姓名」 |
| `workNo` | string | 工号字段；空时可回退 `username` | 列表「工号」 |
| `positionType` | string | 职务字典码（`user_position`） | 列表「职位」；**不要用 `post`** |
| `positionType_dictText` | string | 职务中文（切面补） | 有则优先展示 |
| `orgCode` | string | 当前登录所选部门编码 | 再调 S3 换所属部门名 |
| `orgCodeTxt` | string | 所属部门名称（列表接口会填） | S4/S5 可直接展示部门 |
| `sex` | int | `1` 男 / `2` 女 | 选人表「性别」 |
| `sex_dictText` | string | 如「男」 | 选人表展示用这个 |
| `phone` | string | 手机 | 选人表；`izHideContact=1` 时前端显示 `/` |
| `email` | string | 邮箱 | 同上 |
| `status` | int | `1` 正常 / `2` 冻结 | 选人表「状态」 |
| `status_dictText` | string | 如「正常」 | 选人表展示用这个 |
| `izHideContact` | string | `0` 否 / `1` 是 | 隐藏手机/邮箱 |
| `avatar` | string | 头像 | 可选 |
| `delFlag` | int | 逻辑删除，列表默认已排除 | 不用展示 |

### 5.3 部门对象常用字段（S2 / S3 / S6）

| 字段 | 类型 | 说明 | 怎么用 |
|------|------|------|--------|
| `id` | string | 主键；**保存 `deptId` 用这个** | 配置/筛选 |
| `departName` | string | 部门名称 | 回显优先用这个 |
| `orgCode` | string | 组织编码 | 与用户 `orgCode` 对应 |
| `parentId` | string | 父部门 id | 树结构 |
| `orgCategory` | string | `1` 公司 / `2` 组织 / `3` 岗位 / `4` 子公司 | 选改善部门时选「部门」节点即可 |
| `departPathName` | string | 全路径名（S2 会尝试填充） | `org_code` 不规则时可能报错或为空，**优先 `departName`** |
| `status` | string | `1` 启用 / `0` 停用 | 一般只选启用 |

S6 树节点在上述字段外还有：`key`/`value` = `id`，`title` = `departName`，`isLeaf`，`children[]`。

### S5 用户分页列表（委员会 / 批准人选人）

对应截图「选择批准人」：账号、姓名筛选 + 单选表格 + 分页。

```http
GET /sys/user/list
```

走 Jeecg `QueryGenerator`。鉴权：登录即可（无 `RequiresPermissions`）；带 `@PermissionData`，若当前账号在「用户管理」配了数据权限会收窄结果，管理员一般能看到全量。

| 参数 | 必填 | 说明 |
|------|------|------|
| `pageNo` | 否 | 默认 `1` |
| `pageSize` | 否 | 默认 `10` |
| `username` | 否 | 账号。Jeecg `JInput` 会加星号做 LIKE，如 `*600084*`；手写也可传 `*600084*` |
| `realname` | 否 | 姓名，同上，如 `*汪*` |
| `status` | 否 | `1` 仅正常账号 |

**`result`：** MyBatis-Plus 分页 `{ records, total, current, size }`。`records[]` 字段见 §5.2。选人表建议列：用户账号 `username`、用户姓名 `realname`、性别 `sex_dictText`、手机 `phone`、邮箱 `email`、状态 `status_dictText`。

确认时取中行的 **`id`**（本仓库 `JSelectUser` 已设 `rowKey="id"`）。组件默认 `rowKey` 是 `username`，提案配置**不要用默认**，否则保存的不是用户主键。

示例：

```http
GET /sys/user/list?pageNo=1&pageSize=10&username=*600084*&realname=*汪*
```

### S6 部门树（新增部门负责人 · 选改善部门）

```http
GET /sys/sysDepart/queryTreeList
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `ids` | 否 | 逗号分隔部门 id；传入则只返回这些节点（回显用）。空 = 全组织树 |

**`result`：** 树数组，不是分页。

```json
{
  "success": true,
  "result": [
    {
      "id": "spexdeptgroupelc0000000000001",
      "key": "spexdeptgroupelc0000000000001",
      "value": "spexdeptgroupelc0000000000001",
      "title": "电气组",
      "departName": "电气组",
      "parentId": "...",
      "orgCode": "A01A02",
      "orgCategory": "2",
      "isLeaf": true,
      "children": []
    }
  ]
}
```

保存配置只取 **`id`** 作为 `deptId`。`JSelectDept` 可能返回数组或逗号串，提交前收成单个 id。  
`sync=true` 时组件会改调 `/sys/sysDepart/queryDepartTreeSync`（按父节点懒加载），提案配置页当前是一次性拉全树（`sync=false`），对接 S6 即可。

列表筛选「改善部门」若只要**已配置**的部门，用 B1，不要用 S6。

### S4 按部门选用户（部门负责人弹窗）

先选改善部门，再按该部门（及 `org_code` 前缀匹配的下级）列出**状态正常**人员。

```http
GET /sys/user/queryUserComponentData?departId=<deptId>&pageNo=1&pageSize=10
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `departId` | 建议 | `sys_depart.id`。未选部门时**不要调**，前端给空列表 |
| `pageNo` / `pageSize` | 否 | 默认 1 / 10 |
| `username` / `realname` | 否 | 模糊匹配，**不用**自己加 `*`（后端已 `%xx%`） |
| `id` | 否 | 按用户 id 精确查（回显翻译用） |

**`result`：** 分页，元素同 §5.2。`password`/`salt` 会被后端清空。`orgCodeTxt` 为所属部门名。

### S1 用户批量查询（回显）

```http
GET /sys/user/queryByIds?userIds=id1,id2,id3
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `userIds` | 是 | 逗号分隔的 `sys_user.id`，不要传工号 |

**`result`：** 用户数组（不是分页），字段同 §5.2。本接口**不会**填 `orgCodeTxt`；所属部门需用返回的 `orgCode` 再调 S3。  
委员会弹窗「选中后展示姓名、工号、部门、职位」就是：S1 得 `realname` / `workNo` / `positionType`，S3 得部门名。

### S2 部门批量查询（回显）

```http
GET /sys/sysDepart/queryByIds?deptIds=id1,id2
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `deptIds` | 是 | 逗号分隔的 `sys_depart.id` |

**`result`：** 部门数组：`id`、`departName`、`orgCode`、`departPathName`（尝试填充）。优先 `departName`。若抛「编码长度必须能被固定位数整除」，catch 后降级显示 id，不要让整页挂掉。

### S3 按组织编码取部门

```http
GET /sys/sysDepart/getDepartName?orgCode=A01A02
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `orgCode` | 是 | 来自用户 `orgCode`，不是部门 id |

**`result`：** 单个部门对象（或查不到时为 `null`），取 `departName`。用于提案人**所属部门**、委员所属部门回显（≠ 改善部门 `deptId`）。

选人/选部门组件注意：Jeecg 有时返回 **数组或逗号串**，提交配置前务必收成**单个 id**。

## 6. 提案配置

除特别说明外：保存均为 `POST` + JSON Body；删除均为 `DELETE ?id=`（Vue3 可用 `joinParamsToUrl: true`）。无 `id` = 新增，有 `id` = 更新。

### 6.1 部门负责人（C1–C3）

**列表** `GET /proposal/admin/config/deptLeader/list` → **分页** `{ records, total }`。每行已带嵌套：

```json
{
  "id": "...",
  "deptId": "sys_depart.id",
  "leaderUserId": "sys_user.id",
  "dept": { "id": "...", "departName": "电气组", "orgCode": "S01A02" },
  "leader": { "id": "...", "realname": "张小朋", "workNo": "600088", "positionType": "主任工程师", "orgCode": "S01A02", "deptName": "电气组" },
  "updateBy": "admin",
  "updateTime": "2026-08-28 15:43:15"
}
```

表格：改善部门 `dept.departName`；负责人 `leader.realname` / `leader.workNo` / `leader.positionType`。未配负责人时 `leaderUserId` 与 `leader` 为空。

**保存 Body：**

```json
{
  "id": "编辑时传",
  "deptId": "sys_depart.id",
  "leaderUserId": "sys_user.id",
  "remark": "可选"
}
```

| 规则 | 说明 |
|------|------|
| 一部门一行 | 唯一键 `(dept_id, tenant_id)`，重复部门会失败 |
| 编辑时部门不可改 | 前端 `deptId` 禁用 |
| 先选部门再选人 | 人选范围用 S4，限定本部门 |
| 未配负责人 | `leaderUserId` 可空；列表显示「未配置」；小程序提交该部门会被拒 |

列表需前端补：无。保存时不要把 `dept` / `leader` 回传（后端会忽略，但无必要）。

### 6.2 委员会（C4–C6）

**列表** `GET /proposal/admin/config/committee/list` → **分页**。排序：`sort_no`、`seat_no`。每行已带 `user` 嵌套：

```json
{
  "id": "...",
  "userId": "sys_user.id",
  "user": { "id": "...", "realname": "蔡原", "workNo": "600099", "deptName": "MES开发", "positionType": "JAVA开发工程师" },
  "scoreEnabled": 1,
  "seatNo": 1
}
```

表格：`user.realname` / `user.workNo` / `user.deptName` / `user.positionType`。评分职责仍用 `scoreEnabled` + `seatNo` 前端拼。选中员工后的弹窗预览用 **B4**，不要对列表再调 B4。

**保存 Body：**

```json
{
  "id": "编辑时传",
  "userId": "sys_user.id",
  "scoreEnabled": 1,
  "seatNo": 1,
  "memberStatus": "active",
  "sortNo": 0,
  "remark": "可选"
}
```

| 字段 | 说明 |
|------|------|
| `userId` | 一人一行，唯一键 `(user_id, tenant_id)` |
| `scoreEnabled` | `1` 参与后期六维评分；`0` 只审核不评分 |
| `seatNo` | `scoreEnabled=1` 时必填（1–99）；`=0` 时后端会把 `seatNo` 置空 |
| `memberStatus` | `active` 在任 / `inactive` 离任；审核只认在任 |

评分职责展示：`scoreEnabled===1 && seatNo` → `评分席位 N`，否则 `不参与评分`。

### 6.3 批准人（C7–C9）

**列表** `GET /proposal/admin/config/approver/list` → **数组 `List`，不是分页**。只返回 `approver_status=active`。每行已带 `user` 嵌套（`realname` / `workNo` / `deptName` / `positionType`）。前端可包成 `{ records, total }` 给表格。

业务上通常全局一人；原型做成卡片（姓名/工号/部门/职位 + 更换/移除）。签核范围文案可写死展示：「申请单终审 / 计划书终审 / 报告书终审」（后端暂无该字段）。

**保存 Body：**

```json
{
  "id": "编辑时传",
  "userId": "sys_user.id",
  "approverStatus": "active",
  "remark": "可选"
}
```

未传 `approverStatus` 时后端默认 `active`。

### 6.4 改善性质（C10–C12）

**列表** `GET /proposal/admin/config/improvementType/list` → **数组 `List`**（含停用）。排序：`sort_no`、`type_code`。

**保存 Body：**

```json
{
  "id": "编辑时传",
  "typeCode": "SAFETY",
  "typeName": "安全改善",
  "description": "可选说明",
  "sortNo": 1,
  "typeStatus": "active"
}
```

| 规则 | 说明 |
|------|------|
| `typeCode` | 新增必填；字母开头，仅字母数字下划线，最长 32 |
| 编码创建后不可改 | 编辑时后端强制沿用原 `typeCode`，前端应禁用编码框 |
| 编码唯一 | 重复提示「性质编码已存在」 |
| `typeStatus` | `active` / `disabled`；未传默认 `active` |
| 删除 | 已有提案引用该码会失败，提示改为**停用**；未被引用才物理删除（可重用编码） |

停用后：新提案不能再选；旧单靠 `improvementTypesLabel` 回显。

### 6.5 评分维度（C13–C15）

**列表** `GET /proposal/admin/config/scoreDimension/list` → **数组 `List`**。排序：`sort_no`。

种子六维（可改名称/权重/启停，编码一般不要改）：

| dimCode | 种子名称 | 种子权重 |
|---------|----------|----------|
| `tangible` | 有形绩效 | 30 |
| `intangible` | 无形绩效 | 10 |
| `difficulty` | 难易度 | 20 |
| `spread` | 推广性 | 15 |
| `completeness` | 完成度 | 10 |
| `innovation` | 创新性 | 15 |

**保存 Body：**

```json
{
  "id": "编辑时传",
  "dimCode": "tangible",
  "dimName": "有形绩效",
  "description": "可选",
  "weightPct": 30,
  "sortNo": 1,
  "dimStatus": "active"
}
```

`dimStatus`：`active` / `disabled`。前端可对启用项的 `weightPct` 求和，原型要求合计 100%（后端暂不强制校验）。

## 7. 页面 ↔ 接口映射

| Vue3 页面 | 主要接口 |

## 9. 前端注意点（踩坑清单）

1. **列表/详情不要再调 S1/S2/S3**：姓名、工号、部门、职位已嵌在 `user` / `proposer` / `dept` / `leader` / `reviewer` / `approver` / `operator`。选人弹窗才用 S5/S6；选中后预览用 B4。
2. **提案人部门 ≠ 改善部门**：前者是申请人 `orgCode` 对应部门，后者是 `proposal.deptId`。
3. **`improvementTypes` 是 JSON 字符串**：列表筛选传 `*SAFETY*`；展示优先用行内 `improvementTypesLabel`。
4. **状态/性质不要走 Jeecg 字典**：用 B2/B3；Tag 颜色可前端写，文案用接口 Label。改善部门筛选优先考虑 B1（已配置部门），不要和配置页的全量 `JSelectDept` 混用。
5. **批准人 / 改善性质 / 评分维度列表是 `List`**：不是 `{ records, total }`，取数时判断 `Array.isArray`。
6. **选人组件可能返回数组**：保存前收成单个 id（`deptId`、`leaderUserId`、`userId`）。
7. **职位字段是 `positionType`**，不是 `post`。
8. **S2 若因 `org_code` 报错**：只会出现在自绘选部门回显；列表/详情已改走嵌套字段，不再调 S2。
9. **提案管理不要接 add/edit/delete**：即使后端有接口。
10. **改善性质已引用不可删**：引导改停用；编码创建后不可改。
11. **委员 `scoreEnabled=0` 时不要传席位号**；后端会清空 `seatNo`。
12. **删除接口把 `id` 放 Query**：`DELETE .../delete?id=`。
13. **选人 `rowKey` 必须是用户 `id`**：Jeecg `JSelectUser` 默认是 `username`，提案配置保存的是 `sys_user.id`。
14. **选人/选部门不在「管理端-提案*」Swagger 分组**：见 §5.0；重启后端后看「系统-用户」「系统-部门」。
