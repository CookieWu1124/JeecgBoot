# 阿里云短信服务开通配置手册（配合 JeecgBoot）

> **适用**：提案改善个人开发 / 联调环境；短信登录发码走 Jeecg 内置 `DySmsHelper`（阿里云短信）。  
> **日期**：2026-09-05  
> **相关**：[assets/sms-login/](./assets/sms-login/) 流程图 · 配置落点 `jeecg-boot/.../application-*.yml` 的 `jeecg.smsSendType` / `jeecg.oss`

**安全提醒**：AccessKey、Secret、签名审核材料含隐私；**不要**把真实密钥提交进 Git。个人仓 yml 可用占位符，本机或部署机用外置配置覆盖。

---

## 0. 你最终要拿到的东西（清单）

申请完成后手头应有：

| 项 | 用途 | 填到 Jeecg 哪里 |
|----|------|-----------------|
| AccessKey ID | 调短信 API | `jeecg.oss.accessKey` |
| AccessKey Secret | 调短信 API | `jeecg.oss.secretKey` |
| 短信签名名称 | 如「某某科技」 | `jeecg.oss.sms-template.signature` |
| 登录验证码模板 Code | 如 `SMS_123456789` | 见 §4 映射表 |
| （可选）改密/注册模板 | 管理端其它短信场景 | 同映射表其它 key |

登录短信模板正文须含变量 **`${code}`**（Jeecg 发码时只传 `code`）。

---

## 1. 开通阿里云账号与短信服务

1. 打开 [阿里云控制台](https://www.aliyun.com/) 登录（建议企业实名账号）。  
2. 搜索进入 **短信服务**（SMS / 国内消息）。  
3. 若未开通：按引导开通「国内短信」；阅读并同意服务协议。  
4. 确认账号已 **实名认证**（个人或企业；企业签名通过率通常更高）。  
5. 进入短信控制台 → **概览**，确认产品状态正常。

费用：按条计费，可先充值小额或开通后付费（以控制台当前规则为准）。联调阶段用量很小。

---

## 2. 创建 RAM 用户与 AccessKey（推荐，勿用主账号 AK）

1. 打开 **访问控制 RAM** → **用户** → **创建用户**。  
2. 勾选 **OpenAPI 调用访问**，创建后下载/保存 AccessKey（Secret **只显示一次**）。  
3. 为该用户授权（二选一即可联调）：  
   - 系统策略：`AliyunDysmsFullAccess`（短信完整权限，联调最快）；或  
   - 自定义更小权限：仅 `dysmsapi:SendSms` 等（上线前建议收紧）。  
4. 若同一 AK 还要给 OSS 用：再加 OSS 相关策略；Jeecg 里 **短信与 OSS 共用** `jeecg.oss.accessKey` / `secretKey`。  
5. 个人开发机：把 AK 写进本机 `application-dev.yml` 或外置配置，**勿 push 真实值**。

---

## 3. 申请短信签名

1. 短信控制台 → **国内消息** → **签名管理** → **添加签名**。  
2. 常见填写：  
   - **签名名称**：将显示在短信开头【签名】；须与公司简称/App 名等规范一致。  
   - **签名来源**：按实际选（企事业单位名 / App / 商标等）。  
   - **证明文件**：营业执照、应用商店截图等（按控制台要求上传）。  
3. 提交后等待审核（通常数小时～1～2 个工作日）。  
4. 状态变为 **审核通过** 后，签名名称原样填入 yml 的 `signature`（不要加【】括号）。

提案小程序短信登录目前只强依赖 **登录验证码** 场景；签名通过即可继续申请模板。

---

## 4. 申请短信模板（登录验证码）

1. 短信控制台 → **国内消息** → **模板管理** → **添加模板**。  
2. **模板类型**：验证码。  
3. **模板内容**示例（变量名必须是 `code`）：

```text
您的验证码为${code}，5分钟内有效，请勿泄露给他人。
```

4. 申请说明写清用途：企业内部提案改善小程序登录验证。  
5. 审核通过后记下 **模板 CODE**（形如 `SMS_xxxxxxxxxx`）。

### 与 Jeecg 枚举的映射关系（重要）

代码里默认模板码在 `DySmsEnum`：

| 场景 | 枚举默认 templateCode | 发码入口 |
|------|----------------------|----------|
| 登录 / 忘记密码 | `SMS_175435174` | `/sys/sms` 且 `smsmode=0` 或 `2` |
| 修改密码 | `SMS_465391221` | `/sys/sendChangePwdSms` 等 |
| 注册 | `SMS_175430166` | `/sys/sms` 且 `smsmode=1` |

yml 的写法是：**左边 key = 枚举默认码，右边 value = 你在阿里云申请到的真实模板 CODE**。  
`DySmsHelper` 会用 value 覆盖实际发送的 `templateCode`；若 value 为空，则直接拿左边默认码去阿里云发（一般会失败，因为那是 Jeecg 演示码）。

短信登录联调 **至少** 配好登录模板这一行：

```yaml
jeecg:
  smsSendType: aliyun
  oss:
    accessKey: '<你的 AccessKeyId>'
    secretKey: '<你的 AccessKeySecret>'
    # endpoint / bucketName 若暂不用 OSS 可保持原样
    sms-template:
      signature: '<审核通过的签名名称>'
      templateCode:
        # 登录（及忘记密码共用同一枚举码）
        SMS_175435174: 'SMS_你的登录模板CODE'
        # 以下联调短信登录可不配；管理端其它功能需要时再申请
        SMS_465391221: ''
        SMS_175430166: ''
```

配置文件位置（按 active profile）：

- 个人开发常用：`jeecg-boot/jeecg-module-system/jeecg-system-start/src/main/resources/application-dev.yml`
- Docker / 公司 DEV：外置 `application-docker.yml`（参见 `docs/improve/deploy/`），**密钥不要写进个人仓模板的真实值**

改完 yml 后 **重启** 后端进程。

---

## 5. 控制台自测（不经过 Jeecg）

1. 短信控制台 → **快速学习** / **API 示例** 或使用「发送短信」测试（若有）。  
2. 也可用阿里云 CLI / OpenAPI 调试 `SendSms`：签名 + 模板 + 手机号 + `{"code":"123456"}`。  
3. 手机能收到后，再接到 Jeecg，避免一次排查太多环节。

---

## 6. 接到 JeecgBoot 后怎么验

1. 确认 `jeecg.smsSendType: aliyun`（不要误开成 `tencent`）。  
2. Redis 已启动（验证码存在 Redis）。  
3. 管理端或 Apifox 调（匿名接口，已在 Shiro 放行）：

```http
POST /jeecg-boot/sys/sms
Content-Type: application/json

{
  "mobile": "你的手机号",
  "smsmode": "0"
}
```

`smsmode`：`0` 登录模板 · `1` 注册 · `2` 忘记密码。

4. 看后端日志：`短信接口返回的数据` 中 `Code:OK` 为成功；常见失败：  
   - `isv.SMS_SIGNATURE_ILLEGAL`：签名未过审或名称不一致  
   - `isv.SMS_TEMPLATE_ILLEGAL`：模板码错误或未过审  
   - `isv.INVALID_PARAMETERS`：模板变量不是 `code`  
   - `InvalidAccessKeyId.NotFound` / 签名错误：AK 配错  
5. 同一手机 **10 分钟内** 重复发码：Jeecg 会提示验证码仍有效（Redis 未过期）。  
6. IP 短时刷接口会被 `DySmsLimit` 拦住（需图形验证码那条链路）；联调勿狂点。

手机号登录验码（基座自带，与后续「工号+手机+HR」新接口不同）：

```http
POST /jeecg-boot/sys/phoneLogin
Content-Type: application/json

{
  "mobile": "你的手机号",
  "captcha": "短信里的验证码"
}
```

该接口按 **手机号** 查 `sys_user.phone`；短信登录新方案落地前，仅作「阿里云 + Jeecg 发码链路」冒烟。

## 7. 与提案「短信登录」方案的关系

| 阶段 | 说明 |
|------|------|
| 现在（本手册） | 只开通阿里云 + 配好 Jeecg，保证 `DySmsHelper` 能发出 `${code}` |
| 后续开发 | 发码前先调 HR、换 openid、写 Redis 快照；再调用同一套阿里云发送 |
| 双分支 | 真实 AK / 签名 / 模板码：个人环境配个人 yml；公司环境配公司侧配置，**不要**把个人公网密钥 cherry-pick 进公司仓 |

## 8. 申请时建议填写备忘（可复制）

```text
用途：企业内部「提案改善」微信小程序登录验证码
签名：________（公司简称/产品名）
模板类型：验证码
模板内容：您的验证码为${code}，5分钟内有效，请勿泄露给他人。
变量：code（6 位数字，由业务系统生成）
发送频率：单用户约 60 秒一条；业务侧另有日限额
```
