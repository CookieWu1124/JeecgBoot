## 术语：发码 ≠ 换 openid（勿混）

| 说法 | 指什么 |
|------|--------|
| **发码** | 向用户手机发送 **6 位短信验证码**（阿里云等短信通道） |
| **微信 `code`** | `wx.login` 一次性凭证，点「获取验证码」时随工号、手机一并传给发码接口 |
| **换 openid** | 发码接口**内部前置步骤**：后端用 `code` 换 openid，做绑定检查并写入 Redis 票据 |

**发码 ≠ 换 openid。** 换 openid 只是发短信前顺带做的身份识别，不能凭 openid 直接登录。

## 通道策略（已拍板）

| 通道 | 目标态 | 开发 / 测试期 |
|------|--------|----------------|
| 小程序短信登录（工号+登记手机+验证码） | **正式入口** | 按简化版实现 |
| 小程序微信授权（`/sys/wxMini/*`、getPhoneNumber） | **停用** | **保留**页面/入口/接口，便于产品回切与复用 |
| 小程序工号+密码（`/sys/mLogin`） | **停用** | **保留**，方便联调切换用户 |
| PC 管理端账号密码 | **保留** | 与小程序互不影响（会话约 7 天） |

## 简化版相对完整版的要点

1. 微信 `code` **只在发码**取一次；登录只带工号+手机+验证码。  
2. 后端用 `code` 换 openid，与验证码、HR 回传写入同一张 Redis 票据（5 分钟）。  
3. 发码顺序：格式 → IP 限额 → 换 openid → **先查绑定冲突** → HR 是否在职 → 冷却/日限 → 发短信。  
4. HR **只判是否在职**（工号+手机一次交给 HR）；在职则带回姓名/组织/三级审批人；缺字段存空不挡发码。  
5. 登录只核验 Redis 验证码；用票据里的 openid 写绑定、用 HR 回传建档/更新。  
6. Token：空闲滑动 24 小时；退出只清 Token，不解绑。
