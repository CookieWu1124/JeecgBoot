# 手机短信登录流程（简化版 · 定稿）

> **归档**：`docs/improve/assets/sms-login/`（2026-09-05）  
> **配套图**：[短信验证登录开发流程图-简化版.png](./短信验证登录开发流程图-简化版.png)  
> **通道策略**：短信为正式目标态；小程序 **微信授权 / 工号+密码** 为「**目标态停用、开发期保留**」（页面与 `/sys/wxMini/*`、`/sys/mLogin` 先不动，便于联调与产品回切）。PC 管理端仍账号密码。

小程序用 **工号 + 人事登记手机号 + 短信验证码** 登录。工号只能填工号，不能填用户名或姓名。

是否在职、手机号是不是登记号，以 **HR 系统**为准。微信 openid 只防止一台微信绑多个工号、一个工号绑多台微信，不能凭 openid 直接登录。

会话按空闲计算：最后一次成功请求起 24 小时内再用，过期时间往后推；连续 24 小时没有请求，必须重新收验证码。退出只清登录态，不解除微信绑定。PC 管理端仍是账号密码、7 天，和小程序互不影响。

---

## 员工侧

打开小程序。本地 token 还没空闲超时，直接进工作台。否则进登录页，填工号和人事登记的手机号，点「获取验证码」。

点获取时，小程序向微信要一次 `code`（一次性，用过即废），连同工号、手机号交给后台。后台校验通过后，生成 6 位数字发到该手机，并在 Redis 里存 5 分钟。登录页提示验证码已发送、5 分钟内有效；60 秒内不能再点。

用户把短信里的 6 位填回去点登录。后台从 Redis 取出刚才存的码比对，对上才发卡。过期、填错、已经用过，都过不去。连续填错 5 次，该工号+手机锁定 10 分钟。

同一手机：60 秒只能申请 1 次，自然日最多 10 条。同一来源 IP：自然日最多申请 20 次。超了提示「发送过于频繁，请稍后再试」。

## 发码

入参：工号、手机号、微信 `code`。`code` 只在这一步取，登录不再取。

按下面顺序处理，前面失败就停，不发短信、不调 HR。

### 1. 格式

工号、手机号不能空。手机号按国内 11 位，去掉空格和 `+86` / `86` 前缀后再校验。不对返回「请填写工号和手机号」或「请填写正确的手机号」。

### 2. IP 次数

对该 IP 当天计数加 1。超过 20 次，返回「发送过于频繁」。IP 用连接来源地址，不信客户端自己报的地址。

### 3. 换 openid

用 `code` 向微信换 openid。前端不能传 openid，传了也不用。换不到，返回「无法获取微信登录态，请重试」。

### 4. 绑定唯一性（先做，再问 HR）

查本系统已有绑定：

- 这个 openid 已经绑了别的工号 → 「该微信已绑定其他工号，请联系管理员」
- 这个工号已经绑了别的微信 → 「该工号已绑定其他微信，请联系管理员」
- 没绑过，或本来就是这对 → 继续

这一步只查不写。写入绑定放在登录成功之后。

本系统该工号若已冻结、注销，返回「该账号不可用」，不调 HR。

### 5. HR 是否在职

上面都通过后，把 **工号 + 手机号** 交给 HR。HR 只判断是否在职，不要再拆一次「号对不对」。

| HR 结果 | 处理 |
|---|---|
| 在职 | 同一条结果带回姓名、中心、部门、组别，以及一级、二级、三级审批人的姓名和工号。缺的字段存空，不挡发码 |
| 离职 / 非在职 | 提示「该账号不可用」，不发短信 |
| 超时或失败 | 不发码，提示「发送失败，请稍后重试」，并告警 |

HR 回传在登录成功后写入员工档案。三级审批人是组织汇报链，给后面提案用，不会自动改掉后台配置的委员会、批准人。HR 在职但本系统还没有这个工号，不挡发码，登录成功时按工号建档。

### 6. 手机冷却和日限额

该手机 60 秒内已经申请过，或当天已满 10 条，返回「发送过于频繁」。冷却用 Redis 占位，没有才允许发。短信通道失败时把冷却清掉，可以马上再试。

### 7. 生成验证码并发送

后台生成 6 位数字。同一份码做两件事：交给短信通道发到该手机；和 openid、HR 回传一起写入 Redis，有效期 5 分钟。通道失败返回「发送失败，请稍后重试」，不写 Redis。成功返回「验证码已发送」。

短信通道只负责把码送到手机。登录时不调用通道的校验接口，只拿 Redis 里的值和用户填写的数字比。

## 登录

入参：工号、手机号、验证码。不再带微信 `code`。

发码时已经换过 openid，和验证码、HR 回传放在同一张 Redis 票据里。登录只核验证码，绑定用票据里的 openid。绑的是点「获取验证码」时的那台微信。5 分钟内换了一台手机再填码，仍会绑到发码那台。要换绑，重新获取验证码。

1. 工号、手机、验证码都要有，手机格式要过。
2. 该工号+手机已经连续失败 5 次 → 「失败次数过多，请10分钟后再试」。
3. 从 Redis 取出票据。没有记录，就是过了 5 分钟或根本没发过。
4. 用户填写的数字和票据里的验证码做字符串比较。对不上：失败次数加 1，返回「工号、手机号或验证码不正确」。
5. 用票据里的 openid 写绑定：还没绑过就写入「工号 ↔ openid」；已经是这对就不动。绑定冲突提示联系管理员，不记失败次数。
6. 用票据里的 HR 回传，按工号更新或开通档案（姓名、中心、部门、组别、三级审批人）。
7. 删掉票据和失败次数。签发 token，写入 Redis，24 小时；之后每次成功请求把过期时间重新推 24 小时。

## Redis

| Key | 存什么 | 何时写 | 何时读 / 删 | 多久失效 |
|---|---|---|---|---|
| `wxmini:sms:ticket:{工号}:{手机}` | 验证码、openid、HR 回传（姓名、中心、部门、组别、三级审批人） | 短信发出后写入 | 登录取出比对，成功立刻整张删掉 | 5 分钟 |
| `wxmini:sms:cd:{手机}` | 冷却占位 | 准备发码时写入（没有才写成功） | 已有则拒绝再发；短信失败删掉 | 60 秒 |
| `wxmini:sms:day:{日期}:{手机}` | 当天已发条数 | 发码前加 1 | 大于 10 拒绝 | 1 天 |
| `wxmini:sms:ip:{日期}:{来源IP}` | 当天该 IP 申请次数 | 发码请求进来就加 1 | 大于 20 拒绝 | 1 天 |
| `wxmini:sms:fail:{工号}:{手机}` | 登录填错次数 | 验证码不对时加 1 | 到 5 次锁 10 分钟；登录成功删掉 | 10 分钟 |
| 登录 token 对应的 key | 当前会话 | 登录成功写入 | 每次业务成功把有效期重置为 24 小时 | 24 小时（滑动） |

同一工号+手机再次发码成功，覆盖旧票据，旧验证码作废。

## 微信绑定

绑定记在第三方账号表，类型为小程序。一台微信对应一个工号，一个工号对应一台微信。

发码时只检查冲突，不写表。登录成功且尚未绑定，才写入。退出登录不删绑定。换人、换机由管理员删掉对应绑定后，再走一遍短信登录。

openid 不能用来换新 token。空闲超时必须重新收验证码。

## 接口

| 做什么 | 要带什么 | 说明 |
|---|---|---|
| 发码 | 工号、手机号、微信 code | 先查绑定，再问 HR，通过后发短信，Redis 存 5 分钟票据 |
| 登录 | 工号、手机号、验证码 | 比对票据验证码，用票据里的 openid 和 HR 回传，发卡 |
| 静默登录 / 工号校验 / 微信绑手机（`/sys/wxMini/*`） | — | **目标态停用**；**开发期保留**接口与前端入口，勿删 |
| 小程序工号+密码（`/sys/mLogin`） | — | **目标态停用**；**开发期保留**，便于切换测试用户 |

| 情况 | 提示 |
|---|---|
| 没填或手机格式不对 | 请填写工号和手机号 / 请填写正确的手机号 |
| 60 秒冷却、当天 10 条、IP 当天 20 次 | 发送过于频繁，请稍后再试 |
| 当前微信已绑别的工号 | 该微信已绑定其他工号，请联系管理员 |
| 该工号已绑别的微信 | 该工号已绑定其他微信，请联系管理员 |
| HR 返回离职，或本系统账号冻结/注销 | 该账号不可用 |
| 短信通道失败，或 HR 超时 | 发送失败，请稍后重试 |
| 短信已发出 | 验证码已发送（5 分钟内有效） |
| 验证码错、过期、已用过 | 工号、手机号或验证码不正确 |
| 连续填错 5 次 | 失败次数过多，请10分钟后再试 |
